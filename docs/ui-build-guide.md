# UI build guide: adding screens to Circularity

How to add a new screen so it matches the existing local UI and uses the shared mock-data layer.

## 1. Visual style: copy the existing pages

The reference page is `src/app/(workbench)/command/exceptions/page.tsx`. New pages must look like it:

| Element | Style used in the local app |
|---|---|
| Page title | `text-2xl font-extrabold text-[#141416] tracking-tight` + description `text-xs text-[#6B7280]` |
| Cards / sections | `bg-white rounded-2xl border border-[#E2E8F0] p-4 shadow-2xs` |
| Card heading | `text-sm font-extrabold text-[#141416]` + optional amber icon tile (`bg-[#FFFBEB] border-[#FEF3C7]`, `text-amber-500`) |
| Body text | `text-xs`; secondary `text-[#64748B]`; muted `text-[#94A3B8]` |
| Table header | `text-[11px] font-bold text-[#64748B] uppercase tracking-wider`, rows `border-b border-[#F8FAFC] hover:bg-[#F8FAFC]` |
| Primary button (one per screen) | `bg-[#FFD600] hover:bg-[#FACC15] text-[#141416] rounded-xl text-xs font-extrabold` |
| Secondary button | `bg-white border border-[#E2E8F0] hover:border-gray-400 rounded-xl text-xs font-semibold` |
| Inputs / selects | `bg-[#F8FAFC] border border-[#E2E8F0] rounded-xl text-xs focus:border-[#FFD600]` |
| Status pills | High `bg-[#FEE2E2] text-[#B91C1C]`, Medium `bg-[#FEF3C7] text-[#D97706]`, Low/OK `bg-[#ECFDF5] text-[#047857]`, Info `bg-[#E0F2FE] text-[#0284C7]`, Neutral `bg-[#F1F5F9] text-[#475569]`. Red and green pill text is one shade darker than the base colour so it meets WCAG AA (4.5:1); keep `#DC2626` / `#059669` for icons, dots and charts. In code use `statusTone` from `src/theme/tokens.ts`. |
| Count badges | Red badges are white on `#DC2626` (not `#EF4444`, which is below 4.5:1). |
| KPI values | `text-2xl font-black font-mono text-[#141416]` |
| Numbers and IDs | `font-mono` now means the regular UI font (Geist Sans) with even-width digits (`tabular-nums`), not a monospace face. Keep using `font-mono` for IDs, amounts, timestamps and hashes so they line up in columns. |
| Table alignment | Text, status pills, progress bars and IDs: left (header and cells). Numbers, amounts, percentages and counts: right, set with the column's `align: 'right'` so header and cells match. Action buttons: right. |
| Table separators | Light vertical lines between columns are applied globally to antd tables (`globals.css`); don't add borders per page. |
| Long text | Prefer `truncate` / `line-clamp-2` / column `ellipsis` to keep columns narrow. `AutoTooltip` (mounted in `WorkbenchLayout`) shows the full text on hover or focus whenever text is cut off; add `data-tip="…"` to show a different text. Don't add `title` attributes just for this. |
| Icons | **lucide-react only** in new code (the app uses Lucide in the sidebar and Exceptions). 14–16px inline, 18–20px for actions. No emoji. |
| Route colours | `src/constants/routes.constants.ts` (`DISPOSITION_ROUTES[id].color`) |

The shared components already follow this style. Use them rather than rebuilding:

- `src/components/ui`: `PageHeader`, `Panel`, `MetricCard`, `StatusBadge` / `SeverityBadge` / `StageBadge` / `PriorityBadge`, `TrendIndicator`, `ProgressBar`, `FilterBar` / `SearchInput` / `FilterSelect`, `DataTable` (antd Table with skeleton, empty and no-results states), `Skeleton` / `KpiSkeletonRow` / `TableSkeleton` / `ChartSkeleton` / `ListSkeleton`, `EmptyState` / `NoResultsState` / `ErrorState`, `CaseLink`.
- `src/components/charts`: `BarChart`, `HorizontalBarChart`, `LineChart`, `DonutChart`, `PieChart`, `StackedBarChart` (also `grouped`), `SegmentedBar`, `Sparkline`. They animate on mount (every navigation, via `app/(workbench)/template.tsx`), not on filter changes, and respect `prefers-reduced-motion`.

Chart rules:
- Use one y-axis per chart; two measures with different scales get two charts.
- Charts with 2 or more series always have a legend.
- Use a bar chart to compare categories, a line chart for trends, a donut only for a few parts of a whole, and a table for exact values or row actions.

## 2. Data: JSON → service → hook

- **JSON** lives in `src/data/<domain>.json`. The core dataset is generated by `scripts/gen-mock-data.mjs` (cases, exceptions, tasks, alerts, users, history, capacity, meta). Reference real IDs from it: case IDs `RT-1001`…`RT-1128`, users in `users.json`, sites `Warehouse 1` / `Warehouse 2` / `Repair centre`, tenants `Customer A/B/C`. The "as of" time is `2026-11-20T09:00:00Z`.
- **Services** live in `src/services/<domain>Service.ts`. Use the helpers in `src/services/mock/mockUtils.ts`:
  - `createCollection(json)` gives an in-memory, mutable store. Edits persist while the user navigates, and `subscribe` notifies listeners.
  - `delay()` simulates latency.
  - `queryList()` handles search, filter, sort and pagination.
- Components **never import JSON directly**. They call services through `useServiceQuery(fetcher, deps, { subscribe })` in `src/hooks/useServiceQuery.ts`:
  - On first load, show a skeleton (`initialLoading`).
  - On refetch, keep the old rows on screen.
- Every visible control must do something real: change data through the service, open a modal or drawer, download a file, or navigate. If an action can't be implemented, don't show it.
- For feedback, use `message` and `Modal` from `antd`, as the existing pages do.

## 3. Layout, density and motion rules (Nov 2026 clean-up)

### No horizontal scrolling
Run `node scripts/check-overflow.mjs <routes…>` (needs the dev server on :3000) before you finish. It must pass:
- At **1024px and wider**, neither the page nor anything inside it may scroll sideways.
- **Below 1024px**, the page itself may not scroll sideways.
- Canvases (React Flow) are exempt. Avoid `data-allow-scroll`; use it only if there is truly no other option, and say so.

How to get there:
- **Tables:** use `DataTable` from `src/components/ui`.
  - Give each column a `priority`: 1 = essential, 2 = shown from 768px, 3 = shown from 1200px.
  - Keep 4–6 columns at priority 1–2.
  - Merge related columns: ID + name in one cell, status + age in one cell.
  - Long text gets `ellipsis` plus a tooltip.
  - Anything hidden must be reachable from the row's drawer or expanded row.
  - Below 768px the table renders as cards automatically.
  - Never use `scroll={{ x }}`, `overflow-x-auto` or `min-w-[…]` on tables.
  - A plain `<table>` is allowed only if it follows the same rules (`hidden md:table-cell` / `hidden xl:table-cell`, `truncate`), with no fixed % widths and no `whitespace-nowrap` on wide text.
- **Tabs:** antd `Tabs`, which put overflowing tabs into a "more" menu, or a row that wraps. Never a sideways-scrolling tab strip.
- **Filters:** a wrapping row. Show the 2–3 most important filters; put the rest in a "More filters" popover.
- **Header actions:** use `PageActions`: one yellow primary action, secondary actions that fold into "⋯" on narrow screens, and meta text hidden on narrow screens.
- **Grids:** responsive columns (`grid-cols-1 sm:grid-cols-2 xl:grid-cols-4`). Use `min-w-0` on flex and grid children that hold text. Never set fixed pixel widths on content blocks.

### Less, not repeated
- Each page has one title, one purpose sentence, one primary action, and at most 4 KPI cards.
- Each metric has one home page. Elsewhere, link to it; don't copy it. Numbers come from services, never from literals in the page.
- Remove decorative extras:
  - journey bars that aren't tied to a case;
  - footer disclaimers;
  - "Last refreshed" text that isn't real;
  - Share and Export buttons that do nothing;
  - toggles that don't change content.
- Secondary detail goes behind a drawer, an expanded row, a collapsible panel or a "Show more".
- Give the page room: `space-y-6` between sections, `p-5` inside cards, one border per section, and no cards nested inside cards. KPI icon tiles can stay, but at most one coloured tile per card.

### Loading and motion
- Every page loads through a service with `useServiceQuery`. On first load show skeletons (`KpiSkeletonRow`, `TableSkeleton`, `ChartSkeleton`, `ListSkeleton`), never an empty flash.
- Every chart uses `src/components/charts` (`BarChart`, `HorizontalBarChart`, `LineChart`, `DonutChart`, `StackedBarChart` with `grouped` support, `SegmentedBar`, `Sparkline`) or `ProgressBar`. Don't hand-draw SVG or `div` bars. The shared components animate on each page open, not on filter changes, and respect reduced motion.

## 4. Next.js 16 notes

- Read `node_modules/next/dist/docs/` before using a new API.
- Pages are client components (`'use client'`).
- Don't call `useSearchParams` without a `<Suspense>` boundary. To read query params on load, read `window.location.search` inside an effect.
